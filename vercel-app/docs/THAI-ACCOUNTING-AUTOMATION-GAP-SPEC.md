# 태국 회계-신고 자동화 Gap Spec (V1)

## 범위

- 입력원장: `bank_transactions`, `petty_cash_transactions`, `expense_accruals`
- 분개원장: `journal_entries`, `journal_lines`
- 세무보조장부: `vat_ledger_entries`, `withholding_tax_ledger_entries`
- 신고 준비: PP30, PND3/53, PND50/51

## 현재 확인된 주요 갭

### P0 (즉시 보완)

1. 거래 수정/삭제 시 분개 정합성 미흡
- 신규 생성 시 자동분개는 존재하나, 수정/삭제 API는 분개 역처리/재처리가 일관되지 않음.
- 영향: 시산표와 원거래 불일치, 마감 전 검토시 수기 정정 필요.

2. 마감월 불변성의 부분 적용
- 분개 작성 시에는 `ACCOUNTING_PERIOD_CLOSED` 차단이 있으나, 일부 수정/삭제 경로는 동일 기준 보호가 약함.
- 영향: 마감 후 원거래 변경으로 기간별 재무수치 변질 위험.

### P1 (월신고 자동화 핵심)

3. WHT 신고(PND3/53) Export 부재
- WHT ledger CRUD는 존재하나 신고 제출용 집계/CSV Export가 약함.
- 영향: 회계사가 월별 수기 재집계 필요.

4. 세무코드/폼 매핑 표준화 부족
- VAT/WHT/CIT 코드와 신고 폼 항목 간 매핑의 DB 표준 테이블 부재.
- 영향: 거래 분류/검증 로직이 화면·API별 분산.

### P2 (법인세 고도화)

5. PND50/51 과세소득 조정 엔진 부재
- 경영용 P/L은 존재하나 세무조정(가산/차감)과 중간예납 계산 로직 없음.
- 영향: 반기/연말 법인세 준비에 스프레드시트 의존.

6. 신고 패키지 운영 통제 부족
- 신고 진행률/누락 검증/마감-정정 워크플로우의 통합 대시보드 미흡.
- 영향: 마감 체크리스트 누락 및 책임 추적 어려움.

## 우선순위 실행 순서

1. 분개 정합성 공통유틸 + 수정/삭제 API 연결
2. 태국 세무코드/폼 매핑 스키마 및 기간 유틸 도입
3. VAT/WHT 신고 집계/CSV Export 강화
4. CIT(PND50/51) 계산 엔진 + 신고 패키지 API
5. 컴플라이언스 대시보드 통합(진행률/누락/잠금)

## 완료 판단 기준

- 거래 생성/수정/삭제 후 동일 기간 재집계 시 시산표 차이 0
- 마감월의 원거래/분개 변경 시도는 차단 또는 역분개 정책으로만 허용
- PP30/PND3/53/PND50/51 준비 데이터 Export를 ERP에서 생성 가능
