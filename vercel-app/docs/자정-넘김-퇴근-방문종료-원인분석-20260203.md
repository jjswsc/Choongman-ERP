## 원인 1: 퇴근 (submitAttendance) — "오늘 출근" 조건

### 위치
`vercel-app/app/api/submitAttendance/route.ts` 91~106행

### 문제 코드
```javascript
if (logType === '퇴근' || logType === '휴식시작' || logType === '휴식종료') {
  const hasInToday = (logs || []).some(
    (r) =>
      (r.log_at ? new Date(r.log_at).toLocaleDateString('en-CA', { timeZone: TZ }) : '') === todayStrVal &&
      String(r.log_type || '').trim() === '출근'
  )
  if (!hasInToday) {
    return NextResponse.json({
      success: false,
      message: '출근을 먼저 기록해 주세요. 오늘 출근 기록이 없으면 휴식·재개·퇴근을 기록할 수 없습니다.',
    }, { headers })
  }
}
```

### 동작
- 퇴근/휴식시작/휴식종료를 하려면 **"오늘"(todayStrVal)** 날짜에 출근 기록이 있어야 함.
- `todayStrVal` = 방콕 기준 **현재 날짜**.

### 자정 넘김 시나리오
| 시점 | 방콕 시각 | todayStrVal |
|------|-----------|-------------|
| 출근 | 2월 2일 14:00 | 2026-02-02 |
| 퇴근 | 2월 3일 00:30 | 2026-02-03 |

- 출근: `rowDate = 2026-02-02`
- 퇴근 시점: `todayStrVal = 2026-02-03`
- `hasInToday`는 `rowDate === todayStrVal` 일 때만 true
- 따라서 `2026-02-02 === 2026-02-03` → false
- 결론: **출근을 먼저 기록해 주세요** 응답 → 퇴근 불가

### 원인
자정을 넘긴 퇴근의 경우, 출근은 **전날**에 이루어졌는데, 출근 체크는 **오늘**만 검사함.  
오후/심야 근무의 퇴근은 익일 새벽에 이루어지므로 이 조건을 그대로 적용하면 항상 실패함.

## 원인 2: 매장 방문 종료 (checkUserVisitStatus) — "오늘" 방문만 조회

### 위치
- `vercel-app/app/api/checkUserVisitStatus/route.ts`
- `vercel-app/app/api/getTodayMyVisits/route.ts`

### 문제 코드 (checkUserVisitStatus)
```javascript
const today = new Date().toLocaleDateString('en-CA', { timeZone: TZ })
const list = (await supabaseSelectFilter(
  'store_visits',
  `visit_date=eq.${today}&name=eq.${encodeURIComponent(userName)}`,
  ...
))
```

### 동작
- `active` 여부는 **오늘(visit_date = today)** 인 방문만 조회해서 판단.
- `active === true`일 때만 "방문 종료" 버튼이 활성화됨. (`visit-tab.tsx` 269행: `disabled={!activeVisit}`)

### 자정 넘김 시나리오
| 시점 | 방콕 시각 | visit_date (DB) |
|------|-----------|-----------------|
| 방문 시작 | 2월 2일 23:00 | 2026-02-02 |
| 방문 종료 시도 | 2월 3일 00:30 | - |

- 조회 조건: `visit_date = 2026-02-03`
- 실제 방문 시작: `visit_date = 2026-02-02`
- 해당 방문이 조회되지 않음 → `active = false` → "방문 종료" 버튼 비활성화 → 버튼을 눌릴 수 없음

### 원인
자정 이후에도 종료 가능한 방문은 **전날 시작한 방문**인데, 상태 조회는 **오늘 날짜**만 사용함.

---

## submitStoreVisit(방문종료)는 정상 동작

`submitStoreVisit`의 방문종료 처리:
- `name` + `store_name`로 최근 10건 조회 (`visit_date` 무관)
- 최신 `방문시작`을 찾아 duration 계산 후 종료 저장

즉, **서버에 API 호출까지 되면** 방문종료는 저장됨.  
문제는 `checkUserVisitStatus`가 `active: false`를 반환해서 **"방문 종료" 버튼이 비활성화**되는 것임.

## 수정 방향 (참고용, 아직 적용 안 함)

1. **submitAttendance (퇴근)**
   - 자정 넘김(예: 00:00~06:59 방콕)인 경우, `hasInToday`에 **전날 출근**도 포함해서 검사.

2. **checkUserVisitStatus**
   - 00:00~06:59 등 "새벽" 시간대에는 **어제(visit_date)** 에 시작한 미종료 방문도 조회.
   - 해당 방문이 있으면 `active: true`로 반환해 방문종료 버튼 활성화.

3. **getTodayMyVisits**
   - "오늘 방문 기록" 표시는 그대로 `visit_date = today` 유지 가능.
   - 단, 자정 넘김 방문을 "오늘" 기록에 포함할지 여부는 UI 요구에 따라 결정.
