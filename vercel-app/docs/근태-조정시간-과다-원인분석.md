# 근태 조정(Adjustment) 시간 과다 표시 - 원인 분석

> 사용자 보고: 지각을 조금만 했는데도, 근무시간이 계획보다 조금 늦었는데도 조정 시간이 419분, 403분처럼 과다하게 표시됨

---

## 1. 조정 칸에 표시되는 값의 출처

### 1-1. UI 표시 로직 (admin-tab.tsx / attendance/page.tsx)

조정 Input의 **defaultValue** 계산:

```
diffMin < 0 (조퇴)   → row.earlyMin ?? Math.abs(row.diffMin)
diffMin > 0 (연장)   → row.otMin ?? row.diffMin (30분 이상일 때)
lateMin > 0 (지각)   → Math.max(1, row.lateMin)
```

- **row.earlyMin**: DB `attendance_logs.early_min` (퇴근 로그 시 저장된 값)
- **row.diffMin**: `실제 근무시간 − 계획 근무시간` (분). API에서 매번 재계산

### 1-2. early_min이 저장되는 시점 (submitAttendance)

**퇴근** 시:
```
earlyMin = (계획 퇴근 시각 - 실제 퇴근 시각) 분
        = (pOutDate - nowTime) / 60000
```

- `pOutDate` = `parsePlanTimeToDate(todayStrVal, planOut)`
- `todayStrVal` = 방콕 기준 **현재 날짜** (퇴근 버튼을 누른 시점의 날짜)
- `planOut` = 스케줄에서 가져온 계획 퇴근 시각 (예: "18:00", "02:00")

## 2. 문제 원인

### 2-1. 【주요 원인】타임존 미반영 (같은 날 출퇴근에서도 418·415 분)

`parsePlanTimeToDate`가 서버 로컬(UTC)로 `planOut`을 해석함. **plan_out은 방콕 시각**인데 UTC로 처리되어 7시간 치우침 발생.

| 항목 | 내용 |
|------|------|
| 서버 | Vercel = UTC |
| plan_out | "20:00" = 방콕 20:00 = UTC 13:00 |
| 잘못된 해석 | "20:00" → 20:00 UTC (= 다음날 03:00 방콕) |
| 사례 | 퇴근 20:01 방콕(=13:01 UTC) vs 잘못된 pOutDate 20:00 UTC → earlyMin ≈ **419분** |

**결과**: 같은 날 출퇴근(09:58-20:01, 09:14-18:04)인데도 조정 칸에 418, 415 등 표시.

### 2-2. 【부가 원인】자정 넘김 퇴근 + 전날 스케줄 날짜 오류

| 시점 | 방콕 시각 | todayStrVal |
|------|-----------|-------------|
| 출근 | 3월 10일 14:00 | 2026-03-10 |
| 퇴근 | 3월 11일 00:30 | 2026-03-11 |

전날(yesterday) 스케줄 사용 시, `plan_in_prev_day=false`이면 planOut(18:00)은 **당일 18:00**이어야 함.  
하지만 `parsePlanTimeToDate(todayStrVal, planOut)`을 사용해 **익일 18:00**으로 잘못 해석 → earlyMin 과다.

## 3. diffMin vs early_min 불일치 이유

- **diffMin**: getAttendanceRecordsAdmin에서 **출근·퇴근 시각**과 **스케줄(계획)**을 올바르게 매칭해 `실제 근무시간 - 계획 근무시간`으로 계산.
- **early_min**: submitAttendance에서 **퇴근 시점**에 계산해 퇴근 로그에 저장. 이때 `parsePlanTimeToDate(todayStrVal, planOut)` 사용.

→ diffMin은 **행 기준 날짜(dateForRow)**와 **자정 넘김 시 익일 퇴근**을 정확히 처리함.  
→ early_min은 **퇴근 시점의 todayStrVal**과 **전날 스케줄의 plan_in_prev_day** 처리 실패로 잘못된 pOutDate 사용.

| **주요 원인** | `parsePlanTimeToDate`가 planOut을 서버(UTC) 시각으로 해석. plan_out은 방콕 시각인데 7시간 오차로 earlyMin 과다 (같은 날 20:01 퇴근 → 418·419분) |

## 5. 적용한 수정 (2026-03-11)

### 5-1. parsePlanTimeToDate 방콕 시각 반영

- `planOut`을 **방콕(UTC+7)** 시각으로 해석: `YYYY-MM-DDTHH:mm:ss+07:00`
- 서버가 UTC여도 18:00/20:00이 올바르게 UTC로 변환되어 비교

### 5-2. plan_in_prev_day 반영

- 전날 스케줄 사용 시:
  - `plan_in_prev_day === true` → `parsePlanTimeToDate(todayStrVal, planOut)` (익일 퇴근)
  - `plan_in_prev_day !== true` → `parsePlanTimeToDate(yesterday, planOut)` (당일 퇴근)

### 5-3. 26:00 형식 지원

- plan_out이 "26:00" 등 24시간 이상일 경우 익일로 자동 처리
