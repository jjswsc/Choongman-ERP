# 공지사항 푸시 알림 점검 목록

휴대폰에서 공지 알림이 안 올 때 아래 항목을 확인하세요.

## 1. 시스템 설정

- **설정 > 알림** 또는 admin 설정에서 `공지사항 푸시`가 **켜져 있는지** 확인
- `system_settings` 테이블: `push_notice_enabled` = 1 (또는 true)

## 2. 수신자 등록

- 공지를 받을 직원이 **홈 화면에서 "푸시 받기"** 버튼을 눌러 토큰을 등록했는지 확인
- `push_tokens` 테이블에 `store`, `name`으로 해당 직원 토큰이 있는지 확인

## 3. Firebase 설정

- **FIREBASE_SERVICE_ACCOUNT_JSON**: 서버(API) 환경 변수 설정 여부
- **NEXT_PUBLIC_FIREBASE_*** : 클라이언트 `.env.local` 또는 Vercel env 설정
- `scripts/generate-firebase-sw.cjs`가 dev/build 시 실행되어 `public/firebase-messaging-sw.js` 생성

## 4. 수신자 매칭

- **대상자 지정** 사용 시: 선택된 직원만 수신
- **매장/역할** 사용 시: `getRecipientsByTargetStoreRole`로 employees 테이블의 store, name, role/job 기준 매칭
- `employees` 테이블에 store, name이 있어야 함

## 5. 모바일 제약 (휴대폰에서 알림 안 올 때)

- **Chrome 앱에서 직접 접속** 필수 (카카오톡·인스타그램 등 앱 내 브라우저에서는 푸시 미지원)
- **접속 방법**: Chrome 앱 실행 → 주소창에 배포 URL 직접 입력 → 접속
- **권한**: "푸시 받기" 클릭 후 알림 허용
- **Android**: 설정 → 앱 → Chrome → 알림 → 켜짐, "웹사이트" 채널 소리/진동 확인
- **Android 배터리**: 설정 → 앱 → Chrome → 배터리 → "제한 없음" 권장
- **토큰 재등록**: 오래된 토큰은 무효화됨 → Chrome에서 사이트 접속 후 "푸시 받기" 다시 클릭
- **Vercel 배포 시**: `NEXT_PUBLIC_FIREBASE_*` 및 `FIREBASE_SERVICE_ACCOUNT_JSON` 환경 변수 설정 확인

## 6. 알림이 아예 안 나올 때

- **포그라운드(앱 열림)**: `onMessage` → `setupForegroundHandler`가 알림 표시. 권한 허용 후 페이지 새로고침 필요할 수 있음
- **백그라운드(앱 닫힘/다른 탭)**: Service Worker `onBackgroundMessage`가 처리. `firebase-messaging-sw.js`에 `vibrate`, `silent: false` 포함
- **Android Chrome 알림 채널**: 설정 → 앱 → Chrome → 알림 → "웹사이트" 또는 해당 사이트 채널 → 소리/진동 켜져 있는지 확인
- **배터리 최적화**: 설정 → 앱 → Chrome → 배터리 → "제한 없음" 권장
- **토큰 만료**: 오래된 토큰은 FCM에서 무효화됨. "푸시 받기" 다시 눌러 재등록

## 7. 소리/진동이 안 울릴 때 (다른 각도 점검)

- **data-only 페이로드**: `notification` 페이로드 제거 → 브라우저 자동 표시(무음) 대신 Service Worker가 항상 알림 표시 (vibrate, silent:false 적용)
- **renotify: true**: 동일 tag로 연속 공지 시 이전 알림이 있으면 새 알림으로 덮어쓰며 소리/진동 재생
- **API route 동기화**: `app/api/firebase-messaging-sw/route.ts`도 `public/firebase-messaging-sw.js`와 동일한 옵션(vibrate, silent, renotify) 적용
- **웹 푸시 한계**: Web Notifications API는 `sound` URL 미지원. 플랫폼 기본 소리 사용. Android Chrome은 알림 채널 설정에 따름

## 8. 디버깅

- sendNotice API: `sendFcmToRecipients` 호출 후 `sent`, `failed` 개수 확인 (Vercel 로그)
- FCM이 `sent: 0, failed: 0`이면: recipients가 비어있거나, push_tokens에 토큰이 없거나, Firebase 미설정

## 9. Service Worker 확인 (휴대폰에서 계속 안 될 때)

- **SW 스크립트**: 휴대폰 Chrome에서 `https://[배포URL]/firebase-messaging-sw.js` 접속
- **확인**: `apiKey`, `projectId` 등이 비어 있지 않은지 확인 (빈 문자열이면 env 미주입)
- **rewrite**: `next.config`의 `rewrites`로 `/firebase-messaging-sw.js` → `/api/firebase-messaging-sw` 연결되어 있어야 함 (Vercel 배포 시 env 주입)
- **SW 재등록**: Chrome 설정 → 사이트 설정 → 해당 사이트 → 저장된 데이터 삭제 후, 사이트 재접속 → "푸시 받기" 다시 클릭

## 9. Service Worker 확인 (휴대폰에서 계속 안 될 때)

- **SW 스크립트 확인**: 휴대폰 Chrome에서 `https://[배포URL]/firebase-messaging-sw.js` 접속
- `apiKey`, `projectId` 등이 비어 있으면 → Vercel 환경 변수 `NEXT_PUBLIC_FIREBASE_*` 미설정
- **rewrite**: `next.config.ts`에 `/firebase-messaging-sw.js` → `/api/firebase-messaging-sw` rewrite로 env 주입
- **캐시**: 이전에 빈 설정으로 등록된 SW가 캐시됐을 수 있음 → Chrome 설정 → 사이트 설정 → 해당 사이트 → 저장된 데이터 삭제 후 재접속

## 9. Service Worker 확인 (휴대폰에서 계속 안 될 때)

- **SW 스크립트 확인**: 휴대폰 Chrome에서 `https://[배포URL]/firebase-messaging-sw.js` 접속
- **apiKey·projectId 확인**: 페이지에 `apiKey: "AIza..."`, `projectId: "xxx"` 등이 보여야 함. 빈 문자열이면 Vercel/환경 변수 미설정
- **rewrite 동작**: next.config의 rewrite로 `/firebase-messaging-sw.js` → `/api/firebase-messaging-sw` 연결. 배포 후 적용 확인

## 9. Service Worker 확인 (휴대폰에서 계속 안 될 때)

- **SW 설정 확인**: 배포 URL + `/firebase-messaging-sw.js` 접속 → 소스 보기
- `firebaseConfig`에 `apiKey`, `projectId` 등이 **비어 있지 않은지** 확인 (빈 문자열이면 env 미주입)
- **Vercel**: Project Settings → Environment Variables에 `NEXT_PUBLIC_FIREBASE_API_KEY`, `NEXT_PUBLIC_FIREBASE_PROJECT_ID` 등 설정 후 재배포
- **rewrite**: `next.config.ts`에 `/firebase-messaging-sw.js` → `/api/firebase-messaging-sw` rewrite가 있어야 env 주입됨
