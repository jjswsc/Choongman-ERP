### 1.3 데이터 특성

- **행 단위**: 영수증 내 **메뉴 1건당 1행**
- **결제 금액**: 영수증의 **첫 행**에만 입력됨 → **모든 매출액은 결제 금액 기준**으로 산출
- **채널 구분**: `테이블` 컬럼으로 구분
  - `Lineman 1`, `Shopee 1` → 배달
  - `Table 4`, `Table 9` → 매장(테이블)
  - `Packing 1` → 포장/테이크아웃
- **결제수단**: 현금, 카드, Line Delivery, QR Pay 등

## 2. 매출 관리 메뉴 구조 제안

### 2.1 메뉴 위치

**옵션 A (권장)**  
- **회계** 섹션에 메뉴 추가  
- `손익계산서` 바로 아래: **매출 관리** (`/admin/sales-management`)

**옵션 B**  
- **POS** 섹션 하위에 메뉴 추가  
- POS 정산과 매출 분석을 함께 사용하는 흐름에 적합

### 2.2 페이지 탭 구성

```
┌──────────────────────────────────────────────────────────────────────────────┐
│  매출 관리                                                       [엑셀 업로드]  │
├──────────────────────────────────────────────────────────────────────────────┤
│  [업로드 내역]  [기간별 요약]  [배달앱별]  [채널상세]  [메뉴별]  [결제수단별]      │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   (탭별 분석 영역)                                                            │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 탭 | 내용 |
|----|------|
| **업로드 내역** | 업로드한 엑셀 목록(월/기간, 건수, 총매출). 재업로드·삭제 가능 |
| **기간별 요약** | **월별·주간별·일별·요일별** 매출. 서브뷰 전환 + **매장별** 필터 |
| **배달앱별** | Grab / Line Man / Shopee / Robinhood / 매장 / 포장 별 매출·비율 + **매장별** 필터 |
| **채널상세** | Table 4, Lineman 1, Packing 1 등 개별 채널별 세부 매출 + **매장별** 필터 |
| **메뉴별** | 메뉴별 판매 수량·금액 순위. 검색·정렬 + **매장별** 필터 |
| **결제수단별** | 현금/카드/Line Delivery 등 결제수단별 매출 + **매장별** 필터 |

엑셀 `포스` 컬럼(POS 1, POS 2 등) = 매장/단말 구분 → 모든 탭에서 **매장(포스)별** 검색 필터 제공.

### 2.3 기간별 요약 — 서브뷰 상세

| 서브뷰 | 설명 | 출력 예시 |
|--------|------|-----------|
| **월별** | 월 단위 매출 합계 | `2025-11: 1,200,000฿` / `2025-12: 1,350,000฿` / `2026-01: 1,100,000฿` |
| **주간별** | 주 단위 매출 합계 (월·일요일 시작) | `1/1~1/7: 280,000฿` / `1/8~1/14: 310,000฿` |
| **일별** | 일 단위 매출 합계 | `1/1: 45,000฿` / `1/2: 52,000฿` |
| **요일별** | 요일별 매출 합계 (해당 기간 내) | `월: 180,000฿` / `화: 195,000฿` / `수: 210,000฿` … `일: 165,000฿` |

## 3. 데이터 저장 설계

### 3.1 Supabase 테이블

```sql
-- 업로드 이력 (메타)
create table pos_sales_imports (
  id uuid primary key default gen_random_uuid(),
  file_name text,
  year_month text,           -- "2026-01"
  row_count int,
  total_sales numeric(14,2),
  created_at timestamptz default now(),
  created_by text
);

-- 상세 데이터 (약 7.8만 행/월 → 파티션 고려)
create table pos_sales_details (
  id bigserial primary key,
  import_id uuid references pos_sales_imports(id) on delete cascade,
  sales_datetime timestamptz not null,
  receipt_no text,
  is_void boolean default false,
  pos text,                  -- "POS 1"
  channel text,              -- Lineman 1, Table 4, Packing 1, Shopee 1
  menu_name text,
  barcode text,
  unit_price numeric(12,2),
  qty int,
  menu_sale_price numeric(12,2),
  receipt_total numeric(12,2),  -- 총 판매가 (영수증 첫행만)
  payment_amount numeric(12,2), -- 결제 금액 (영수증 첫행만) ★ 매출액 집계 기준
  staff text,
  cash numeric(12,2),
  card numeric(12,2),
  line_delivery numeric(12,2),
  -- 기타 결제수단 필요 시 컬럼 추가
  created_at timestamptz default now()
);

-- 인덱스
create index idx_pos_sales_details_import on pos_sales_details(import_id);
create index idx_pos_sales_details_datetime on pos_sales_details(sales_datetime);
create index idx_pos_sales_details_channel on pos_sales_details(channel);
create index idx_pos_sales_details_menu on pos_sales_details(menu_name);
```

### 3.2 대용량 처리

- 7.8만 행/월 수준 → **배치 insert** (500~1000건씩)
- 동일 `year_month` 재업로드 시 **기존 import 삭제 후 재적재** 옵션 제공

## 4. API 설계

| API | 메서드 | 용도 |
|-----|--------|------|
| `POST /api/importPosSalesExcel` | multipart | 엑셀 업로드 후 파싱·DB 적재 |
| `GET /api/posSalesImports` | - | 업로드 내역 목록 |
| `DELETE /api/posSalesImports?id=xxx` | - | 특정 업로드 삭제 |
| `GET /api/posSalesByPeriod` | importId, groupBy, **pos** | 기간별 매출 (pos=매장 필터) |
| `GET /api/posSalesByDeliveryApp` | importId, **pos** | 배달앱별 매출 |
| `GET /api/posSalesByChannel` | importId, **pos** | 채널 상세 |
| `GET /api/posSalesByMenu` | importId, **pos** | 메뉴별 매출 |
| `GET /api/posSalesByPayment` | importId, **pos** | 결제수단별 매출 |

- **매장별 필터**: 모든 조회 API에 `pos` 쿼리 파라미터 지원 (예: `pos=POS 1`). 생략 시 전체.

### 4.1 기간별 집계 API (`posSalesByPeriod`)

| groupBy | 설명 | 응답 형식 |
|---------|------|-----------|
| `month` | 월별 | `[{ yearMonth: "2026-01", sales: 1100000 }]` |
| `week` | 주간별 (일요일 시작) | `[{ weekStart: "2026-01-05", weekEnd: "2026-01-11", sales: 280000 }]` |
| `day` | 일별 | `[{ date: "2026-01-15", sales: 45000 }]` |
| `dow` | 요일별 (0=일 ~ 6=토) | `[{ dow: 1, label: "월", sales: 180000 }]` |

- **주의**: `payment_amount`(결제 금액)는 영수증 첫 행에만 있음 → `receipt_no` + `sales_datetime` 기준으로 **영수증 단위 중복 제거** 후 합산

### 4.2 배달앱 분류 로직 (channel → delivery_app)

저장 시 `channel` 원본값을 유지하고, 조회 시 아래 규칙으로 그룹화:

```js
function getDeliveryAppCategory(channel) {
  const c = String(channel || '').trim()
  if (/^Grab\s/i.test(c)) return 'Grab'
  if (/^Lineman\s/i.test(c)) return 'Line Man'
  if (/^Shopee\s/i.test(c)) return 'Shopee'
  if (/^Robinhood\s/i.test(c)) return 'Robinhood'
  if (/^Table\s/i.test(c)) return '매장'
  if (/^Packing\s/i.test(c)) return '포장'
  return '기타'
}
```

## 5. UI/UX 흐름

1. **업로드**  
   - [엑셀 업로드] 버튼 → 파일 선택 → 업로드 진행  
   - 업로드 완료 시 `year_month` 자동 추출 또는 사용자 선택

2. **필터**  
   - 업로드 내역: 기간(년월) 선택  
   - 기간별 요약: `importId` 단일 선택 또는 **여러 업로드 병합** (월별 비교 시 유용)  
   - 월별 뷰: 여러 달 업로드 시 월간 비교 가능  
   - **매장별**: 모든 탭에서 **포스(POS)** 기준 필터 지원 (POS 1, POS 2 등 → 매장별 검색)

3. **내보내기**  
   - 각 탭에서 엑셀/CSV 다운로드 (기존 패턴 활용)
