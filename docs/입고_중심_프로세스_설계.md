# 입고 중심 프로세스 설계

## 확정된 정책
- **당기매입**: 입고 등록만 반영, 발주 승인 제거
- **미지급금**: 입고 시점, 입고 건별
- **입고 내역**: 수정·연동·삭제 권한 있는 메뉴
- **발주서**: 참조·거래처 발주서 작성용
- **UI**: 발주 → 입고 등록 버튼 → 입고 화면(발주 선택 가능) → 입고 내역 조회에서 최종 결정

---

## 2. 발주–입고 연결 구조 (아이디어)

### 방안 A: inbound_batches 테이블 (권장)
```
inbound_batches
- id (PK)
- location, vendor_name (또는 vendor_code), batch_date
- total_amount (입고 합계)
- purchase_order_id (nullable) ← 발주 연동
- invoice_no (nullable)
- created_at
```
- registerInboundBatch 시 배치 1건 생성
- stock_logs 각 행에 `inbound_batch_id` FK
- 발주 화면에서 "입고 등록" 클릭 → 입고 화면에 purchase_order_id 전달 → 해당 발주의 품목을 기본으로 채움

### 방안 B: stock_logs에 purchase_order_id
- 각 stock_logs 행에 직접 purchase_order_id
- 부분입고: 같은 PO에 여러 번 입고 시, 각 행마다 같은 po_id
- 단점: 한 배치에 여러 PO 품목 섞이면 복잡

### 권장: 방안 A
- 배치 단위가 명확 (한 번 저장 = 한 배치)
- PO 연동은 배치 수준에서 1:1 또는 null(직접구매)
- 부분입고: PO #1에 대해 1차 입고 배치(A), 2차 입고 배치(B) → 각각 별도 배치, 같은 po_id 참조

## 4. 한 번의 통장 출금 ↔ 여러 건 매입 (아이디어)

### 방안 A: bank_transaction_inbound_links 테이블
```
bank_transaction_inbound_links
- bank_transaction_id (FK)
- inbound_batch_id (FK)
- amount (이 출금에서 이 입고에 배분한 금액)
```
- 통장 출금 200만원 시: 배분 100+100 또는 60+80+60
- 미지급금 정산 시 각 inbound에 맞게 차감

### 방안 B: bank_transactions에 inbound_batch_ids (JSON 배열)
- `inbound_batch_ids: [1, 2]`
- 배분 금액은 별도 처리 필요 → 복잡

### 방안 C: 1:1만 허용 (단순)
- 한 통장 출금 ↔ 하나의 입고 배치만 연동
- 200만원 = 2건 합산이면, 100만원+100만원으로 2번 출금 등록

### 권장: 방안 A (유연)
- 실제로 한 번에 여러 건 결제하는 경우 대응
- UI: 통장 출금 수정 시 "입고 건 연동"에서 여러 건 선택 + 금액 배분

## 구현 순서

### Phase 1: DB + 손익계산서
1. inbound_batches 테이블 생성, stock_logs.inbound_batch_id 추가
2. payable_transactions: ref_type='Inbound', ref_id=inbound_batch_id 지원
3. processPurchaseOrderApproval: upsertPayableFromPO 제거
4. getIncomeStatement: 발주(purchase_orders) 당기매입 제거 (입고만 유지)

### Phase 2: 입고 → Payable
5. registerInboundBatch: inbound_batches 생성, stock_logs에 batch_id, payable 생성(ref_type=Inbound)

### Phase 3: UI
6. 발주 화면: "입고 등록" 버튼, 해당 PO의 품목을 입고 화면으로 전달
7. 입고 화면: 발주 선택(또는 직접구매), PO 선택 시 품목 pré-remplir
8. 입고 내역 조회: 수정·연동·삭제 기능

### Phase 4: 통장 ↔ 입고 연동
9. bank_transaction_inbound_links 테이블
10. 통장 거래 UI: 입고 건 연동 선택 (다건+금액 배분)
