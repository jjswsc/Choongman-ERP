## 2. 현재 방식의 한계

1. **수동 관리**: 엑셀 수기 입력, 시트 간 반복 데이터, 날짜 Excel serial 혼재
2. **실적 불일치**: Campaign Performance는 수동 입력, POS 실제 매출과 자동 연동 없음
3. **비용 분리 부족**: 광고·인플루언서·제작비가 회계(은행/ petty cash)와 별도 관리
4. **연계 분석 부재**: 캠페인 ↔ POS 매출 ↔ 지점 ↔ 메뉴 간 자동 교차 분석 없음

### 3.2 POS 연계 설계

**연계 포인트**: `pos_sales_details` (매출 상세)

| POS 컬럼 | 마케팅 매칭 |
|----------|-------------|
| `channel` | 캠페인 형식: Lineman→Delivery, Table→Dine in, Packing→Carry out |
| `menu_name` | 프로모션 메뉴/세트 이름 (키워드 매칭 또는 pos_promos 연동) |
| `sales_datetime` | 캠페인 기간 내 여부 |
| `pos` (또는 store) | 참여 지점(Branch) |

**자동 매칭 로직**:
1. **캠페인-기간-채널 매칭**: `sales_datetime` ∈ [campaign.start_date, campaign.end_date] 그리고 channel ↔ format
2. **프로모션 메뉴 매칭**: `pos_promos` + `pos_promo_items` 에 캠페인 ID 연결 시, 해당 프로모션 적용 주문만 집계
3. **지점 매칭**: `pos` ∈ campaign.branches (지점명 정규화 필요: MBK, Sukhumvit 12, True Digital Park 등)

**집계 결과 저장** (선택):
- `marketing_campaign_results`: campaign_id, period, dine_in_orders, delivery_orders, dine_in_sales, delivery_sales
- 기간별/캠페인별 자동 집계로 "Campaign Performance" 대체

---

### 3.3 회계 연계 설계

**연계 포인트**: `bank_transactions`, `petty_cash`

| 마케팅 비용 | 회계 처리 |
|-------------|----------|
| Ads (Online) | bank_transactions: memo에 "광고" 또는 별도 계정과목 "Advertising" |
| Ads (Offline) | Standy/Tentcard/Prop/Coupon → "Marketing - Offline" |
| Production | "Marketing - Production" |
| Food | "Marketing - Sample/Sample food" 또는 재고 출고 |
| Influencer | "Influencer fee" 또는 "Marketing - Influencer" |

**연계 방식**:
1. **memo 규칙**: `marketing_campaign_id:xxx` 또는 `marketing_campaign:캠페인명` 태그
2. **bank_memo_rules** 확장: 마케팅 관련 키워드 → campaign_id 자동 매핑
3. **손익계산서**: 마케팅 비용 계정과목 별도 항목, campaign별 필터링 가능

**데이터 흐름**:
```
bank_transactions (또는 petty_cash)
  → memo / account_subject
  → marketing_campaign_id (규칙 기반 또는 수동 연결)
  → marketing 캠페인 비용 실적 자동 합산
```

---

### 3.4 매출 관리(sales-management) 연계

- **채널별 매출**: 이미 `posSalesByChannel` (Lineman, Table, Packing 등) 제공
- **마케팅 보강**: 채널별 매출에 "캠페인 기간" 필터 추가 → 캠페인 기간 내 Lineman 매출 = 해당 Delivery 캠페인 실적 참고
- **메뉴별 매출**: `posSalesByMenu` + 캠페인별 프로모션 메뉴 필터

## 4. 마케팅 메뉴 UI 구성 제안

### 4.1 메뉴 위치

**적용**: 마케팅 관리 = 별도 대메뉴 (매출 관리, 매장 관리, 인사 관리와 동일 레벨), 매출 관리 바로 아래 위치.

```
매출 관리
├── 매출 관리
마케팅 관리        ← 별도 대메뉴 (NEW)
├── 캠페인        → /admin/marketing/campaigns
├── 광고 ROAS     → /admin/marketing/ads
├── 인플루언서    → /admin/marketing/influencers
├── 실적 대시보드 → /admin/marketing/dashboard
└── 비용 연계     → /admin/marketing/costs
매장 관리
├── 점검
├── 방문
└── ...
```

### 4.2 페이지 구성 (별도 메뉴)

각 기능별 별도 페이지. 사이드바 > 마케팅 관리 하위 5개 메뉴.

| 페이지 | 경로 | 기능 |
|--------|------|------|
| **캠페인** | /admin/marketing/campaigns | 캠페인 CRUD, 기간·지점·비용·KPI 입력, 결론, POS 실적 자동 표시, 엑셀 가져오기 |
| **광고 ROAS** | /admin/marketing/ads | 포스트별 플랫폼·예산·실비 입력, ROAS 계산 (매출/광고비) |
| **인플루언서** | /admin/marketing/influencers | 인플루언서 협업 이력, 비용, 플랫폼 링크 |
| **실적 대시보드** | /admin/marketing/dashboard | 캠페인별 KPI vs 실적, 지점별 비교, 프로모션 기간별 트렌드 |
| **비용 연계** | /admin/marketing/costs | 은행/petty 캡처 ↔ 캠페인 매핑, campaign별 비용 집계 |

`/admin/marketing` 접근 시 → `/admin/marketing/campaigns`로 리다이렉트.

## 8. 업그레이드 방안 (Phase 2+)

기본 설계 구현 후, 데이터 정확도·의사결정 지원·운영 효율을 높이는 추가 기능.

### 8.1 POS·쿠폰 정밀 연계 (실적 정확도 ↑)

| 현재 | 업그레이드 |
|------|------------|
| 채널·기간 기반 추정 | **프로모션·쿠폰 실제 적용 주문만** 집계 |

**구현**:
- `pos_promos`에 `marketing_campaign_id` 컬럼 추가 → CM Set 2, 1+1 세트 등 프로모션 ↔ 캠페인 1:1 연결
- `pos_coupons`에 `marketing_campaign_id` 추가 → Deliver Coupon, Sale Here 쿠폰 등 캠페인별 쿠폰 사용량 추적
- POS 주문 시 적용된 프로모션/쿠폰 ID 저장(`pos_orders` 등)하면, 해당 주문을 캠페인 실적에 직접 반영 가능

**효과**: "21 คูปอง" 수동 입력 → 쿠폰 사용 건수 자동 집계, 프로모션 메뉴 주문만 정확히 측정

---

### 8.2 원가·마진 연계 (의사결정 품질 ↑)

| 현재 | 업그레이드 |
|------|------------|
| 매출·비용 위주 | **프로모션 메뉴별 마진·ROI**까지 자동 계산 |

**구현**:
- `pos-cost-analysis`와 연동: 프로모션에 포함된 메뉴의 **원가**를 `getMenuCost`/`getPosMenuCostAnalysis`로 조회
- `마진 = 판매가 - 원가`, `ROI = (매출 - 마케팅비용) / 마케팅비용`
- 대시보드에 "캠페인별 마진", "할인 프로모션 손익" 표시

**효과**: "ไม่ได้ผล ไม่คุ้มค่า"를 숫자로 검증 (예: 할인 20%인데 마진이 마케팅비보다 적으면 손실)

---

### 8.3 인플루언서 성과 지표 (CPF, 효율 비교)

| 지표 | 계산 |
|------|------|
| **CPF (Cost Per Follower)** | 비용 ÷ 팔로워 수 |
| **도달 추정** | 팔로워 × 3~5% (플랫폼 평균) |
| **비교 랭킹** | CPF 낮은 순, 지점별 재방문 인플루언서 추천 |

인플루언서 탭에 CPF 컬럼 추가, 테이블 정렬/필터로 "가성비 좋은 인플루언서" 한눈에 파악.

---

### 8.4 캠페인 템플릿·재사용 (입력 효율 ↑)

반복되는 프로모션(CM Set 2·3·4, 1+1, Sale Here 등)용 **템플릿** 저장:
- 제목, 형식, 할인 구조, 참여 지점 패턴
- 새 캠페인 생성 시 "템플릿에서 복사" → 기간·KPI만 수정

---

### 8.5 예산 알림·리마인더 (운영 효율 ↑)

| 알림 | 조건 |
|------|------|
| 예산 초과 | 실비 > 예산 (광고·인플루언서·캠페인별) |

| 캠페인 종료 | D-day, D-3 알림 (관리자 대시보드 또는 이메일) |

### 8.6 통합 캘린더 뷰 (일정 시각화)

- 월별/주별 뷰
- 클릭 시 상세 (캠페인, 광고, 인플루언서) 표시
- 일정 겹침·공백 분석으로 리소스 배분 확인

### 8.11 프로모션 세트 시뮬레이터 (메뉴 조합·할인 결과 미리보기)

**목적**: 프로모션 세트 구성 시, 메뉴를 섞고 할인 적용 시 **원가·마진·수익성**을 즉시 확인.

**동작 흐름**:
1. **메뉴 선택**: POS 메뉴 목록에서 세트 구성 메뉴 선택 (드래그 또는 체크)
2. **수량 설정**: 메뉴별 수량 (예: Golden Fried 1 + Kimchi Soup 1 + Rice 1)
3. **판매가 입력**: 세트 가격 (또는 할인율 % 입력 → 자동 계산)
4. **결과 즉시 표시**:
   - 정가 대비 합계 vs 세트 판매가 (할인액)
   - 원가 (getPosMenuCostAnalysis / cost-data 기반)
   - 마진 = 세트 판매가 - 원가
   - 마진률 = 마진 / 판매가
   - 목표 주문 수 기준 예상 이익 (마진 × N주문 - 마케팅비)

**표시 예시**:
```
┌─────────────────────────────────────────────────────────────┐
│  CM Set 시뮬레이터                                            │
├─────────────────────────────────────────────────────────────┤
│  [Golden Fried BL] x1  ฿199  원가 ฿45.2                      │
│  [Kimchi Soup S]   x1  ฿99   원가 ฿32.1                      │
│  [Rice]            x1  ฿20   원가 ฿4.5                       │
│  ─────────────────────────────────────────────────────────  │
│  정가 합계 ฿318  │  세트가 ฿299 (6% 할인)  │  원가 ฿81.8   │
│  마진 ฿217.2 (73%)  │  100주문 시 ฿21,720 (마케팅비 ฿1,920 제외 시 ฿19,800) │
└─────────────────────────────────────────────────────────────┘
```

**구현 위치**: 마케팅 > 캠페인 탭 내 "세트 시뮬레이션" 버튼 또는 POS 프로모션 등록 화면에 임베드.

**연계**: `getPosMenuCostAnalysis` / `getMenuCost` API, `pos_menus`, `pos_promo_items` 구조와 호환. 시뮬레이션 결과를 `pos_promos` 신규 등록 시 prefilled 값으로 활용.

### 8.12 LINE OA (공식계정) 연계 (추후 API 활용)

**현황**: Line OA로 회원 다수 확보 → API 연동 시 CRM·마케팅 효과 극대화.

#### 8.12.1 LINE API 활용 영역

| API/기능 | 용도 | ERP 연계 |
|----------|------|----------|
| **Messaging API** | 1:1 메시지, 푸시 | 프로모션 안내, 생일 20% 쿠폰, 신메뉴 공지 |
| **LIFF** | 회원 전용 웹앱 | 포인트·주문 이력, 쿠폰 수령 |
| **Account Linking** | LINE UID ↔ ERP 회원 | line_user_id ↔ members |
| **Membership API** | 회원카드, 쿠폰 발급 | pos_coupons ↔ LINE 쿠폰 동기화 |
| **Broadcast** | 전체 발송 | 캠페인 시작일, 새 프로모션 공지 |

#### 8.12.2 활용 시나리오

| 시나리오 | 흐름 |
|----------|------|
| **생일 쿠폰** | 회원 생일 → 20% 쿠폰 자동 발송 → pos_coupons 등록 |
| **타겟 프로모션** | 3개월 미방문 회원 → CM Set 2 LINE 푸시 |
| **포인트·주문** | LIFF 앱에서 포인트, 과거 주문 확인 (POS 연동) |
| **회원 수 동기화** | OA 팔로워 수 → 마케팅 대시보드 지표 |
| **쿠폰 사용 추적** | LINE 발급 코드 = pos_coupons.code → 캠페인 실적 집계 |

#### 8.12.3 연동 시 데이터 구조

```
line_members (또는 members 확장)
├── line_user_id, display_name, phone, birth_date
├── points, last_order_at, last_visit_store
└── created_at

line_coupon_sends
├── line_user_id, pos_coupon_id, campaign_id
├── sent_at, used_at (POS 사용 시 업데이트)
└── ...
```

#### 8.12.4 사전 준비

- LINE Developers Console: Messaging API 채널, LIFF 앱
- Webhook 서버: 친구 추가, 메시지 등 이벤트 수신
- OA 구독 플랜: 태국 기준 발송 한도 확인
