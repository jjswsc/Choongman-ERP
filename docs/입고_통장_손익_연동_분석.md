# 입고 관리 → 통장 거래 / 손익계산서 연동 분석

## 1. 현재 연동 상태 체크

### 1.1 손익계산서 (Income Statement)

| 구분 | 매입(purchases) 산출 근거 | 입고(stock_logs) 포함 여부 |
|------|---------------------------|----------------------------|
| **본사** | `purchase_orders` 발주서만 | ❌ 미포함 |
| **매장** | `orders` 본사 주문만 | ❌ 미포함 |

- **재고(기초/기말)**: `stock_logs`로 계산 → 입고는 재고에는 ✅ 반영됨
- **당기매입**: 발주서(PO) / 본사주문만 사용 → **입고 관리에서 등록한 직접 구매는 당기매입에 ❌ 누락**
- **결과**: COGS = 기초재고 + 당기매입 - 기말재고 에서, 입고 직접 구매 금액이 당기매입에 빠져 COGS가 부정확해질 수 있음

### 1.2 통장 거래

| 흐름 | 연동 여부 |
|------|-----------|
| 통장 출금(물품 대금) + 거래처 선택 | → `payable_transactions` 자동 생성 (ref_type=Payment, bank_transaction_id) |
| 입고 등록 (`registerInboundBatch`) | → `stock_logs`만 저장. payable 생성 없음. 통장 연동 없음 |

- 입고와 통장 거래는 **자동 연동 없음**
- 입고 시점 ≠ 통장 출금 시점일 수 있어 수동으로도 추적이 어려움

### 1.3 미지급금(Payable)

| 발생 경로 | ref_type | ref_id | 비고 |
|-----------|----------|--------|------|
| 발주서 승인 | PO | purchase_order.id | upsertPayableFromPO |
| 통장 출금(물품 대금) | Payment | null | bank_transaction_id로만 연결 |
| 입고 등록 | - | - | payable 생성 안 함 |

## 2. 개선 방향

### 2.1 손익계산서 - 당기매입에 입고 포함

**방안**: `getIncomeStatement`에서 당기매입 계산 시, `stock_logs` (log_type=Inbound)의 금액도 합산

- **본사**: `purchase_orders` + `stock_logs`(location=입고등록, Inbound)의 sum(qty * unit_cost)
- **매장**: `orders` + `stock_logs`(location=매장명, Inbound, From HQ 제외)의 sum(qty * unit_cost)
- `unit_cost`가 NULL이면 `items.cost` 사용

### 2.2 입고 → 미지급금 자동 생성 (선택)

입고 등록 시 거래처별 금액 합계로 `payable_transactions` 생성:

- ref_type = 'Inbound' (또는 'DirectInbound')
- ref_id = inbound_batch_id (배치 테이블 도입 시) 또는 null
- memo = "입고 YYYY-MM-DD 거래처명"
- 통장 출금 시 이 payable과 매칭 가능하도록 연동

※ 배치 단위 관리가 필요하면 `inbound_batches` 테이블 추가 검토

## 3. 물품 대금 인보이스 파악 문제 및 해결 방안

### 3.1 현재 구조

- `bank_transactions`: `vendor_code`, `purchase_order_id`, `invoice_no`, `invoice_received`, `invoice_photo_url`
- 발주서 있음: `purchase_order_id`로 발주서와 연동 → 어떤 인보이스(발주)인지 파악 가능
- **발주서 없는 직접 구매**: purchase_order_id 없음 → 어떤 인보이스인지 파악 불가

### 3.2 해결 방안

#### 방안 A: 입고 건과 통장 출금 연동 (권장)

1. **입고 배치 테이블 도입** (`inbound_batches`)
   - id, location, vendor_name, batch_date, total_amount, invoice_no, created_at
   - `registerInboundBatch`에서 배치 생성 후 각 `stock_logs`에 `inbound_batch_id` 저장

2. **bank_transactions에 `inbound_batch_id` 컬럼 추가**

3. **통장 거래 UI (물품 대금)**
   - 거래처 선택 후: "입고 건 연동" 선택란 추가
   - 해당 거래처의 미결제 입고 배치 목록 표시 (날짜, 금액, 인보이스 번호)
   - 선택 시 `inbound_batch_id` 저장 → "이 출금이 OO 입고에 대한 결제"로 명확화

#### 방안 B: 인보이스 번호만 강화 (간단)

- 입고 등록 시 "인보이스 번호" 필드 추가
- 통장 출금 시 "인보이스 번호" 입력 필드 강조 (이미 있음)
- 사용자가 수동으로 같은 번호를 입력해 매칭

#### 방안 C: 입고 내역 조회에서 금액/날짜로 추적

- 미지급금/통장 거래 화면에서 "입고 내역 보기" 링크
- 거래처 + 기간 필터로 입고 내역 표시
- 금액·날짜를 비교해 수동으로 어떤 건인지 파악

## 4. 권장 적용 순서

1. ~~**손익계산서**: 당기매입에 입고(stock_logs Inbound) 포함 (필수)**~~ ✅ **적용 완료** (getIncomeStatement)
2. **인보이스 파악**: 방안 A(입고 건 연동) 도입 → B, C는 보완용
3. **입고 → payable**: 입고 시 미지급금 자동 생성 여부는 방안 A와 함께 설계
